**Date:** 2026-10-23. **State:** **U00 COMPLETE (10/10)** with public API manifest, signed architecture/connection handoff contract, executable illegal-transition matrix, real benchmark runner topology and focused PHPForge QA. **U01 COMPLETE (9/9)**; full 3.0 dialer/transport is not yet implemented.

## Development rules

- One established-connection engine for incoming and outgoing streams. Connection attempts, client/server TLS roles, UDP/QUIC and protocol state machines remain separate where behavior demands it.
- Public API breaking changes are allowed for a coherent architecture, but every changed API needs a migration guide and tests.
- No hidden blocking: DNS and filesystem use genuine non-event-loop execution or explicitly reject unsupported modes; keep optional native extensions optional.
- Full 3.0 scope includes networking (TCP/TLS/Unix/UDP/QUIC), async DNS, dialing, pooling, proxies, relay, HTTP1/2/3, WebSocket and WebTransport clients/servers, filesystem, Fiber concurrency, autoscaling, all hosted integrations, security, observability and complete docs.
- 64-bit PHP 8.4+ and Composer remain the baseline. No new dependency or release gate on unrelated Infocyph repositories.
- Follow the mandatory **rolling grouped-batch / overlapping-QA workflow** documented below. Push previous-batch QA corrections together with the next coherent batch whenever safe; do not multiply commits or discard long CI runs solely for minor fixes. Update plan, roadmap and progress journal with each pushed group. Only QA-proven tasks may count as accepted.
- Keep 2.1.2 as immutable baseline. Final matched throughput requires five 180-second pairs, warmup, successful RPS, both CV below 2.5%, strict p99/RSS/correctness budgets, generator headroom, and 1800-second process-tree soak. A passing mock or microbenchmark cannot replace real protocol QA.
- **Sphinx documentation is mandatory:** use **exclusively native reStructuredText (.rst)** for all published documentation pages, with an InterMix-style `docs/conf.py`, `docs/index.rst`, Read the Docs configuration v2, and no MyST or `.md` Sphinx pages. Convert legacy end-user Markdown guides to RST before release. Internal trackers/evidence are outside the published Sphinx source graph. Require, complete detailed feature list, generated PHP API reference, migration guides and strict docs CI. All U16 tasks are required for 3.0.
- **Task proof convention:** change [ ] to [x] only after Acceptance is verified and update Proof from PENDING to immutable commit, real test and Actions/artifact link. No plan-only task completion.

## Rolling grouped-batch development and QA workflow (mandatory)

**Objective:** finish the full Runwire 3.0 scope efficiently without duplicate CI execution, stale trackers, unsafe shortcuts or false task acceptance. This section governs U04–U17 work and supersedes older journal instructions to stop after every small QA push.

1. **Choose related work, not necessarily sequential task IDs.** Group small, independently testable tasks by subsystem and acceptance dependency (for example DNS/TLS deadline propagation, QUIC capability/security gates, QUIC stream lifecycle, HTTP protocol negotiation, resource/soak certification). Prefer lower-complexity and high-unblocking work first. Cross-batch parallelism is allowed, but an unresolved prerequisite cannot be counted as complete.
2. **Batch A — implement and locally/target-test.** Add production code, negative tests, resource/failure tests and documentation; identify exact U task IDs and evidence still missing. Keep all edits in **Runwire**, on `plan/runwire-independent-ecosystem-roadmaps` and the existing **PR #9**.
3. **Push A once and let its normal PR QA run.** Use the existing per-PR workflow behavior; do not add branch-push jobs that duplicate the PR checks. Note A's commit SHA and GitHub run IDs in the journal. Avoid unnecessary pushes while the long H3/adaptive benchmark runs because newer PR commits can cancel older runs.
4. **While A is running, prepare Batch B without pushing immediately.** Develop the next related set of tasks, with targeted tests and tracker notes staged separately. This overlaps useful development with CI instead of idly waiting.
5. **Read A's real QA feedback, not just workflow status.** Inspect the exact failed job and log (Pest, Pint, PHPCS, Rector, PHPStan/Psalm, hosted/native/QUIC, benchmarks). Diagnose and fix failures; do not hide, skip, relax, or reclassify failed gates. If A passes, make no invented QA fix.
6. **Push one combined B + A-recovery commit.** Incorporate A's fixes and B's completed work, plus updated plan/roadmap and tests, **in the same push** when sensible. Then start preparing C while this newest head runs QA. Repeat: `A implementation → A push/QA ∥ B development → (A QA fixes + B) push/QA ∥ C development → ...`. If a critical regression or unsafe native limitation blocks B, split out a safety fix instead of carrying broken code forward.
7. **Keep one authoritative CI head.** A canceled or skipped run is never green evidence. Each accepted task must have a passing, relevant exact-source-run proof; inspect the new head's complete required matrix before promoting it. Avoid repeatedly canceling expensive jobs; deliberately hold the next push when near the end of a long benchmark.
8. **Synchronize the tracker on every push.** In **this plan**, keep each U checkbox, proof, batch Done/total, Open, Status, canonical total, progress percentage, and journal aligned. Update the **roadmap in the same commit** (totals, batch status, R-task crosswalk and blockers). Pending work may be described as *implemented / QA pending*, but its checkbox stays `[ ]`. Acceptance `[x]` requires real tests and linked immutable Actions/artifact evidence. Never count staged, skipped, failing or design-only implementation as full transport acceptance.
9. **Select acceptance by task gate, not by an unrelated green workflow.** Focused correctness and host tests can accept a narrowly scoped concurrency/security task, but U04 matched verified TLS, U05 real independent QUIC session/streams, long-run U15 benchmarks and U17 release gates each require their own specified evidence. Record genuinely unavailable opt-in benchmark dispatch/native dependencies as OPEN and give the next executable step.
10. **Repeat until all 175 tasks are accepted or a specific blocker is documented.** On each cycle, report latest SHA, last-batch QA PASS/FAIL/PENDING, tasks accepted and open, planned next group, and source-backed blockers. Do not merge, tag, release or touch Foundation/Infbyte/Runwire-Core/Runwire-Cells; maintainer handles merge and publication.

**Tracker invariant:** sum of checked Uxx.yy tasks = the canonical accepted total; each of 18 batch rows equals the checked count within that batch; overall open = 175 − accepted; roadmap totals and historical 20-ID crosswalk reflect the same state. `tests/Plan3TrackerSynchronizationTest.php` enforces numeric consistency; human review and cited CI evidence enforce truthful acceptance.

**Immediate rolling example:** Q2-A isolated native QUIC handshake probe → Q2-A source and PHPForge QA; build Q2-B independent aioquic real-server proof in parallel → resolve Q2-A reference/Pint/PHPStan feedback + Q2-B interop + this synchronized workflow in one commit → inspect complete next-head QA before U05 acceptance. U04.08 remains an independently triggered matched-TLS certification task.
