## U10.05 — authenticated SOCKS5 negotiation and DNS policy

- Native Runwire HTTPS proxy transport is authenticated against a trusted proxy TLS peer before *any credentials*; internal dialer provenance, not caller-supplied flags, gates password method negotiation.
- Real PHP/TLS loopback adversarial cases test successful RFC 1929 credentials, password rejection, anonymous authentication method substitution, explicit domain opt-in versus local-only DNS, and verified proxy TLS hostname mismatch before any bytes are written. Source [620730b](https://github.com/infocyph/Runwire/commit/620730bf295e9cd85a9ad187943a252667f015ef).
- A **separate Python TLS RFC1928/1929 reference server**, independent of Runwire protocol implementation, verifies exact credentials, SOCKS5 IPv4 ATYP=1, opt-in remote-DNS ATYP=3, target port 443, and no anonymous downgrade credential transmission. Source [cc1ec90](https://github.com/infocyph/Runwire/commit/cc1ec9011da10ec492d2e6e07932f1a92a2e43ea), including `tests/Socks5IndependentTlsReferenceTest.php` and `tests/fixtures/independent_socks5_tls_server.py`.
- Scope: proxy authentication/CONNECT handoff and DNS leak policy verified; **does not certify nested TLS for the original destination**, which stays U10.06 OPEN. Independent HTTP CONNECT original-peer TLS (U10.04), full pool saturation (U10.09) and WebTransport remain OPEN.
