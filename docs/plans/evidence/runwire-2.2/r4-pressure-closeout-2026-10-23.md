**R4.01 DONE for baseline scope**: [Benchmarks #39890566370](https://github.com/infocyph/Runwire/actions/runs/39890566370) independently exercised TLS HTTP/2 under HPACK dynamic header changes, 16 KiB stream flow windows, slow-receiver backpressure and real concurrency phases. These are **short diagnostic phases, not sustainable throughput figures**.

[Security & Standards #39890566963](https://github.com/infocyph/Runwire/actions/runs/39890566963) validated real aioquic HTTP/3: delayed QPACK header insertions / unblocking, 1 KiB verified uploads, and separate QUIC connections during churn, preserving correctness on every phase. [H3 pressure artifact](https://github.com/infocyph/Runwire/actions/runs/39890566963/artifacts/12474333971). At the high-tier exemplars, H3 QPACK **628.01 successful RPS / 1,099 delayed header events / 18,808 encoder-instruction bytes / 35,057 header-block bytes**, upload **642.69 RPS / 1,323,008 verified upload bytes**, churn **221.65 RPS / 60 separate connections**. Server and client CPU and peak RSS are recorded; neither client nor server result is a production A/B promotion certificate.

**R4 root-cause fixes:** [`2b4eb47`](https://github.com/infocyph/Runwire/commit/2b4eb4791a2e1dc5241e277b53535d0a8a903801) makes legitimate inbound HTTP/2 WINDOW_UPDATE control work earn a **bounded** supplement from genuinely sent DATA; it does not exempt unearned WINDOW_UPDATE, PING or SETTINGS floods. [`dc6169c`](https://github.com/infocyph/Runwire/commit/dc6169c622ba641fc6d79dbfdb3e0148ea13166d) fixes PHPForge method-ordering style. The earlier [failing benchmark #39888712552](https://github.com/infocyph/Runwire/actions/runs/39888712552) and [security #39888712829](https://github.com/infocyph/Runwire/actions/runs/39888712829) are superseded by **complete same-source green** workflows above, not deleted from audit history. No weaker correctness, p99, memory, flood caps or benchmark-CV thresholds were introduced.
